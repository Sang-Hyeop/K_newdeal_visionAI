# 10월 23일 사건 시각 표시와 공용 연결

## 시간 표시

경보·조치 관리에서 영상 최초/최근 경과시간, 이번 재생 기준 발생/최근 시각,
실제 등록·확인·조치 이력을 구분한다. 10/19 등 과거 이력은 덮어쓰지 않는다.
이번 재생 기준 시각은 앱 실행 시각 + 영상 경과초로 환산한 값이며 실제 관측·처리 시각이 아니다. 로그인·탭 이동·새로고침으로 표시 기준 날짜를 다시 잡지 않는다.
현재 재생에서 관측되지 않은 과거 사건은 현재 재생 기준 시각을 만들지 않는다.
원본 경과초가 없는 기록은 임의로 09시에서 빼지 않고 확인 불가로 표시한다.

사건 키, 경보 규칙, 개인 N·체크와 감지 모델은 유지한다. 메인 집계·알림은 탭 밖의 공통 시계로 진행하고, 메인 복귀 시 제거됐던 영상은 세션 진행 위치로 복원한다. 운영 통계의 평균 최초 확인·완료 카드 두 개는 표시하지 않는다. 소리 끄기는 음향만 제어한다.
시연 영상을 새로 시작한다고 별도 사건을 만드는 세션 분리는 도입하지 않았다.

## 서버(이 맥)

프로젝트에서 `python 시선_공용서버.py`를 실행한다. 포트 8020으로 수신한다.
최초 비어 있는 DB에만 로컬 조치 로그를 가져온다. 기존 DB는 재가져오거나 초기화하지 않는다.
서버 접속키는 `.sisun/shared-server.json`, DB는 `outputs/backend/shared_cases.sqlite3`이다.
구버전 episode_id 전용 이력도 원문 보존하며 현재 사건에 추정 연결하지 않는다.
기존 앱은 완전히 종료한 뒤 다시 실행해야 수정 코드와 공용 설정을 읽는다.

## 팀원 PC

GitHub 최종 PR 브랜치(병합 후 main)의 전체 ZIP을 압축 해제한다. 별도 접속 파일은 서버 담당자에게 전달받는다. 공개 GitHub ZIP에는 비밀 접속 파일을 넣지 않는다.
프로젝트 폴더에서 `python 시선_공용연결.py`를 실행한다.
전달받은 접속 파일(기존 `.sisun/팀원_공용사건_접속.json`이 있으면 자동 선택)로 서버 조회에 성공한 뒤에만
개인 `.sisun/shared-cases.json`을 저장한다. 그 다음 시선 앱을 다시 실행한다.
경보·조치 관리 상단의 ‘공용 사건 서버 연결됨’ 표시를 확인한다.
연결 실패 시 기존 설정을 덮어쓰지 않는다.

접속 파일에는 접속키가 있으므로 팀 내부에서만 전달하고 공개 GitHub·Notion에 올리지 않는다.
같은 LAN에서 서버 맥이 켜져 있어야 한다. 운영체제 방화벽의 Python 수신 허용이나
공유기의 단말 격리 정책은 다른 PC 접속에 영향을 줄 수 있다.
이 맥에서 LAN IP를 통한 접속은 확인했지만 다른 물리 PC의 접속과 동일한 검증은 아니다.
IP가 바뀌면 접속 파일의 서버 주소를 갱신해 다시 연결한다.
영상 재생 위치와 N·체크는 동기화 대상이 아니다. 공용 사건의 담당자·조치·이력을 공유한다.

로컬 복귀는 `python 시선_공용연결.py --disconnect` 후 앱을 재실행한다.
공용 DB는 남고 기존 로컬 로그도 보존된다. 환경 변수로 직접 설정한 경우에는
SISUN_CASE_SERVER와 SISUN_CASE_TOKEN도 해제해야 한다.

## 검증

전체 408개 검사 완료, OK(Windows 전용 6개 생략), JavaScript 구문 검사 통과.
별도 임시 DB에서 독립 클라이언트 간 확인·조치 상태 공유, 충돌, 인증 실패,
연결 중단 시 저장 실패를 검사했다. 실제 DB에는 시험 조치나 가짜 완료를 쓰지 않았다.
이벤트·집계·모델 잠금 파일과 로컬 원본 조치 로그의 해시 보존을 확인했다.
