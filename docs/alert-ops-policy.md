# 운영 경보 관리 정책

감지 모델·PPE 승인 정책·위험 판정 임계값과 별개로, **운영자에게 전달하는 경보**만 다룬다.
설정 값은 `dashboard/alert_policy.py`에만 둔다.

## 원본 vs 운영 경보

| 계층 | 내용 | 변경 |
|------|------|------|
| 원본 이벤트 | JSONL·event_id·grade/status | 수정·삭제 금지 |
| 운영 경보 | 에피소드 묶음·알림음·종 목록·확인함 | 본 정책 |

## 묶음 기준

- 시연 세션 `epoch`(로그인·메인 새로고침 시 증가) + 카메라(`area`) + 기능(`scenario`) + 대상 키
- 대상 키: 근접·구역·체류·PPE는 `person_no` 우선, 없으면 `worker`/`track_id`. 불꽃은 `track_id`(예: FIRE2:1)
- 대상 키가 없으면 `event_id` 단독 경보(임의 병합 금지)
- 이벤트 시각 기준 `EPISODE_IDLE_GAP_SECONDS`(기본 5초) 이상 주의/위험이 비면 새 경보
- 추적 ID만으로 세션을 넘기지 않음(epoch로 분리)

## 알림음·카드

| 상황 | 동작 |
|------|------|
| 같은 event_id 재조회 | 무시 |
| 같은 에피소드·같은/낮은 중요도 | 최근 시각·관련 기록 수 갱신, 소리/새 카드 없음 |
| 주의 | 종 목록·화면만(무음) |
| 주의 → 위험 · 새 위험 | 위험음 1회 + 목록 갱신 + 확인 전으로 되돌림 |
| 한 배치 다중 위험 | 목록은 각각, 소리는 1회 |
| 위험음 재생 중 추가 위험 | 목록만 즉시 반영, 소리 대기열·겹침 재생 없음 |
| 다른 대상·카메라·기능 | 독립 경보(기록) |
| 관측 소실·판정 불가 | 경보 대상 아님(안전/종료로 보지 않음) |
| 주기적 재알림 | 이번 단계 미사용(`PERIODIC_RENOTIFY_SECONDS = None`) |

관련 기록 수는 **같은 지속 위험의 원본 행 개수**이며 서로 다른 사고 건수가 아니다.

## 운영자 확인·대응 상태

감지 상태(grade/status)와 **대응 상태**를 분리한다. 관측 소실·주의 하향 등으로 대응을 자동 완료하지 않는다.

| 대응 상태 | 의미 | 다음 단계 |
|-----------|------|-----------|
| 신규 | 경보 발생, 담당자 미확인 | 담당자 확인 |
| 담당자 확인 | 로그인 사용자가 확인 | 조치 시작(내용 입력) |
| 조치 중 | 대응 진행 중 | 조치 완료(확인 내용 입력) |
| 조치 완료 | 담당자가 결과 기록 | (종료) · **현장 안전 보증 아님** |

- 종(벨) 카드에서 상태 전환·한 줄 조치 기록. 별도 티켓 시스템 없음
- **영상 발생 시각**(first/last clock)과 **처리 시각**(버튼 누른 벽시계)을 구분해 표시·저장
- 변경 로그: `dashboard/data/alert_response_log.jsonl` (작업자·이전/다음 상태·내용·시각·`request_id`·`link_key`)
- 저장 성공(HTTP·본문 `ok`) 확인 후에만 화면 대응 상태 갱신. 실패 시 기존 상태·입력 유지, 자동 재시도 없음
- 연결 키 `link_key` = `cam|scenario|subject|e0:anchor_event_id` (epoch 제외). event_id 인덱스로 복원. 시간·카메라 이름만으로 추정 병합하지 않음
- 서버는 저장된 현재 상태·허용 전이만 신뢰. 동시 요청은 잠금·`request_id` 멱등으로 처리
- 대응 변경은 경보·조치 관리의 명시적 버튼으로만 처리한다. 카메라 열기·목록 조회는 대응 상태를 바꾸지 않는다.
- 사이드바 **N**: 새 위험 영상 확인 필요. 해당 영상이 실제 표시되고 로딩된 뒤 그 카메라만 **✓**로 바뀐다. 단순 반복 관측 갱신은 N을 재점등하지 않는다. 위험 해소·조치 완료와 별개다.
- 메인·전체 경보·이벤트 이력·운영 통계 조회는 대응 상태를 바꾸지 않음
- 목록 UI는 브라우저 세션 메모리(새로고침 시 목록 비움). JSONL에 남은 조치는 같은 `link_key`/event_id로 복원
- 알림 억제(`seen_event_ids`·에피소드): 서버 프로세스·시연 세션 단위(로그인/새로고침 시 리셋). 조치 JSONL은 유지
- 유휴 분리 후 활성 에피소드만 갱신(`active_by_base`). 묶음 분리 ≠ 현장 위험 종료
- 화면 용어: 확인 전 / 확인함 / 조치 중 / 조치 완료 (`new/acked/acting/done`)
- 시연용 배정 담당자 A~D는 사건 최초 생성 시 1회 저장. 로그인 처리자와 별도 필드
- 조치 단계·메모·이력 UI는 **경보·조치 관리** 페이지. 종 창은 인지용(조치 관리 이동)
- 구현: `dashboard/alert_response.py`, 페이지 `case_ui.py`·`app.make_cases`, 종 UI는 `dashboard/style.py`

## 시연 재생

- 알림 버스는 세션 벽시계, 오버레이는 영상 `currentTime`(기존 구조 유지)
- 영상 반복·탐색만으로 알림 시계를 되돌리지 않음 → 같은 회차 재처리로 중복 경보 없음
- 메인 새로고침·재로그인 = 새 시연 회차(epoch)로 경보 다시 진행
