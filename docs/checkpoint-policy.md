# 중간 저장 원칙

사용자 요청(2026-10-06): 중간중간 저장할 지점을 알리고 실제 저장한다.

다음 단계가 끝나면 저장한다: 데이터 선정/라벨 수정, 학습 실행 완료(실패 포함), 기능 모듈 연결, 실제 영상 검증, 팀 인계 준비. 모든 작은 수정마다 커밋하지 않고 검토 가능한 결과 단위로 묶는다.

- 완료 내용·미해결 문제·다음 작업을 docs/progress-2026-10-06.md 또는 해당 날짜 진행 기록에 적는다.
- 코드/설정/테스트/검증 지표/입력 스냅샷을 현재 브랜치에 로컬 커밋한다. 기존 단계 검사가 통과했고 이후 기능 변경이 없다면 저장만을 이유로 같은 검사를 반복하지 않는다.
- Git에서 제외되는 pt, 생성 영상, 학습 데이터는 기존 원본을 유지한다. 중요한 모델/시연 출력은 별도 체크포인트 백업을 만들고 파일 경로·바이트·SHA-256 목록을 Git 문서에 기록한다. 대용량 원본 ZIP 전체를 매번 복제하지 않는다.
- 같은 디스크의 복사본은 수정/삭제 복구용이며 디스크 고장에 대한 외부 백업은 아니다. GitHub 코드 저장과 대용량 파일 보관을 구분한다.
- 완료 보고에 커밋 ID와 로컬 저장/GitHub 업로드/main 병합 상태를 명시한다. 기존 사용자 승인 범위에 따라 GitHub 작업을 수행하며 로컬 커밋만으로 업로드했다고 표현하지 않는다.
- 성능이 떨어진 실험은 experimental_not_promoted로 남긴다. 시연 성공을 독립 현장 정확도로 확대해석하지 않는다.
